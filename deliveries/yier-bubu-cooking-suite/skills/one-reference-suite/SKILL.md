# 单图 → 用途适配全套

这是**给具备看图和参考生图工具的Agent执行的Skill**，不是不需模型/工具的离线一键生图程序。用户只给图，分析JSON与提示词由Agent内部完成，不要求用户填表或复制提示词。

## 能力与预算
默认一张输入、一个主题、10次生图：手机、电脑、iPad横屏、iPad竖屏、手表、情头A、情头B、朋友圈、QQ主页、聊天背景。每次只生成一张独立用途原画；不把多张拼在一张生成图里再裁切。UI、尺寸适配、展示板与光点动态为后期，不消耗生图次数。不得将33个导出文件称为33张AI原画。

## 0. 接收与定位
- 本地上传图：直接读取。
- Drive的Windows路径不是本机路径；用已连接Drive按文件名查找，再核对父目录、UI/无UI、字节或MD5。同名不代表同图。
- 先确认实际可读且看过原图，记录源路径、云端ID、MD5。新目录交付，禁止覆盖旧成果。

## 1. Agent看图，创建内部profile
先分类：avatar / wallpaper / ui_screenshot / other。写入：
- visible_entities：实际出现的角色，每个实体独立id和locked身份锚点。
- style_locked：线条、颗粒、上色、色盘、比例、材质。
- scene_adaptation：源场景锚点，或头像未展示背景时可合理设计的简洁场景。
- allowed_changes：用途需要的姿态、表情、小道具、取景、构图变化。

不要只根据文件名猜图。锁定身份与画风，不锁死同一睡姿。头像可以改成头肩近景、面对彼此、互补表情和呼应道具。

### 单主体/信息不足策略
若输入只出现一个主体，默认情头A/B为**同一主体的两种互补姿态**。不凭空断言不存在于图里的伴侣身份、背面花纹、全身服装。用户明确说要Tom/Jerry但只给Tom头像时，可生成指定Jerry，但要标为用户指定补充而非从图中恢复。本次测试图实际同时出现Tom和Jerry，因此配对可以一猫一鼠。

若只有头像，下半身/房间等不可见信息属于合理延展而非“还原原版”。无需为每个小细节询问用户；仅当身份/硬性需求有实质歧义时问。

## 2. 自动规划
执行 `scripts/plan.py --reference 原图 --profile 内部分析.json --out 全新目录`。
- 规划器验证真实图片与profile，创建10个宿主generate_image参数；默认不派发网络调用、不收费、不读取密钥。
- Agent读取tool_jobs.json并调用**当前真实可用的生图工具**，每个任务都附同一原始参考，禁止串行把衍生结果传到下一张导致漂移。
- 如果运行环境没有参考生图工具，明确停在规划阶段，不冒充完成生成。不要默认安装GitHub脚本、索取API密钥或启动外部付费服务。
- 工具不支持原生像素/长宽参数时，把画幅放进提示词，生成后测量并记录真实值；不承诺原生4K。

## 3. 用途路由
|用途|必须适配的内容|
|---|---|
|手机|竖屏，上方时钟区，主体不被通知遮挡|
|电脑|重新绘制横向场景，左侧图标区；不拉伸竖图、不模糊填边|
|平板横/竖|分别生成4:3和3:4，不把一个裁成另一个|
|手表|近景/半身、更简洁，顶部时间区；耳朵/头顶完整|
|情头A/B|分别原生方形近景生成；互补朝向/姿态；不能裁215像素小脸输出1024冒充高清|
|朋友圈|2:1横幅，右下避开头像，不能用手机截图顶替|
|QQ主页|横幅独立取景，头像/昵称区避开脸|
|聊天|中央和上方70%低对比，角色在角落，不直接把繁忙壁纸洗白凑数|

## 4. 逐张视觉检查
看生成总览及关键单图：身份、耳形、脸型、颜色、角色数量、四肢、边缘裁切、主体比例、留白。情头允许用途化改造，但不能改画风。自动尺寸/哈希测试不等于人物语义检查。
失败项不能悄悄以别的图代替；预算内针对性返工，预算满时标出缺陷并征得同意再追加。

## 5. 后期UI与独立交付
参考本仓库 `deliveries/tom-one-input-suite/skills/render.py` 的已测实现；它是Tom本次实例，不可原样把Tom文案套到别的角色，Agent需按profile替换身份标签、配色、源文件映射与UI安全区。
- 无UI、UI分别存储。UI是通用模拟，不称实机截图或可安装主题。
- 手机通知必须放在角色上方空墙；平板横屏图标仅放左侧。
- 情头圆形遮罩只是预览；完整方图保留。情侣壁纸可用完整原生头像缩小组合专用聊天背景，不能裁脸放大。
- 标准4K/平板尺寸为整幅适配导出，尺寸与原生分辨率分列。插值不增加原生细节。
- MP4为程序光点静音循环，不是人物动画；GIF低清预览必须单列。
- 禁止HTML/PDF/ZIP替代独立图片。上传新文件夹后fresh list核对文件数、名称、字节、MD5并处理分页；未上传不得称交付完成。

## 6. 报告边界
向用户报告本次输入类型、用了几个参考、几次生图、原生尺寸、原生近景 vs 裁剪、实际上传数与验收结果。全场景输入一次成功不等于已经实测“任何头像/任何UI截图都必定成功”。本次Tom测试是单张**双角色手机壁纸输入**，头像输入分支仅做了规划单测，尚未做第二轮实际生图验证。

## 已确认的聊天默认风格（用户选择09）
从现在起，聊天背景默认用 references/chat-style-default.json 的「可可晚安灯串」：暖可可/奶油/琥珀配色、上沿细灯串、月亮与少量暖色心形；主体在高度24%–55%，句子「走过你的朝朝暮暮」，配对名字放57%–61%，64%以下留给输入法。角色沿用当前输入，不把Tom/Jerry带到其它题材。保留一定装饰密度，避免再次退回底角小角色+大块空白。UI模拟须展示键盘避让；真实设备高度不同，不能承诺所有输入法均不遮挡。
