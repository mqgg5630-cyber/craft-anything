## 完整流程

### 1. 在本地准备脚本，但不直接下载

沿用同一仓库已验证的受限下载引擎，为新链接设置独立标题校验、输出目录和 Actions 工作流。本地只运行模拟响应的离线测试，没有直接请求小红书或图片 CDN。

脚本：`tools/wallpaper-job/download_koi_dream.py`。

### 2. 推送脚本与工作流

首次合并推送遇到 GitHub 服务端 500。重试后采用先推送下载入口与测试、再推送工作流的顺序，两次推送均成功。没有改成本地网络下载，没有切换工作分支。

工作流：`.github/workflows/koi-dream-download.yml`。触发限定当前会话分支与本次脚本/工作流路径，避免图片写回后循环下载。

### 3. Actions 读取公开笔记

使用正常移动浏览器请求头及公开短链声明的笔记路径；仅允许官方分享、笔记与 CDN 域名。没有使用账号、登录 Cookie、私密凭据，不执行页面脚本，不绕过登录或验证码。标题必须包含“锦鲤”，笔记 ID 必须一致。

### 4. 下载并完整校验

每个公开声明候选均先检查文件结构，再加载全部像素，确认格式、尺寸、单帧及像素上限；按像素面积、字节数选取可得候选。每张上限 12 MiB、整批 65 MiB、最大 2400 万像素、最短边 300 像素，网络请求有超时，页面状态遍历有上限。

检查 SHA-256 重复内容；先在临时目录暂存整批，再复读校验。只有全部通过才发布结果目录；失败不会提交部分原片。

### 5. 校验后写回同一分支

成功运行：<https://github.com/mqgg5630-cyber/craft-anything/actions/runs/45522544591>

原片写回提交：`d2d19a5`。

分支：`arena/cf4bb177-craft-anything`。

使用 `git pull --ff-only` 接收已由 Actions 写回的文件。本次全部真实网络下载发生在 GitHub Actions，不在当前环境直接下载。

### 6. 阅读原片，建立视觉基准

根据实际原片确定：米白纸纹、青碧水色、朱红与白金长尾锦鲤、透明绢纱般鱼鳍、描金水纹、充足留白。保持国风水彩与细线描金，而非 3D、卡通或摄影。参考重绘属于新的 AI 图像，构图细节、鱼鳍与水纹不承诺逐像素一致。

### 8. 有 / 无 UI 分开保存

无 UI 文件保留独立 AI 原画，不改动。用 Pillow 的透明图层另存模拟 UI：金褐色时钟、日期、小祝福、锁、信号/电量与底部快捷操作和横条。日期固定为“11月22日 星期日”、时间 9:41，属于设计模拟，不表示实时设备状态；祝福用 Noto CJK 字体精确排版。

第 02 张为右侧游鲤构图，时钟向左偏移，避免遮挡鱼头。其余时钟居中。界面不添加设备外壳，也不是实际系统截图。

### 9. 总图与验收

生成有/无 UI 总对照图、两套分类总图与原片总图；检查鱼数和构图、字体、时钟留白与两版对应关系。离线验收数量、完整解码、原生尺寸、字节、SHA-256、MD5、原片不变、成品互异及 UI 非破坏性。

## 复核与重建

在仓库根目录运行：

```sh
.venv/bin/python -m unittest discover -s tools/wallpaper-job -p 'test_download*py' -v
.venv/bin/python -m unittest discover -s tools/wallpaper-job -p test_koi_dream_package.py -v
.venv/bin/python tools/wallpaper-job/package_koi_dream.py
.venv/bin/python tools/wallpaper-job/archive_koi_dream.py
```

解压完整 ZIP 后，也可在交付目录内运行（需 Python 3.10+、Pillow 11.3.0）：

```sh
python 04-复现资源/package_koi_dream.py --root .
```

此命令读取已保存的十张无 UI 图，使用包内字体重建 UI、预览和校验清单；不访问网络、不上传、不重生成 AI 图像，不覆盖无 UI 与原片。下载脚本只供 GitHub Actions 使用，不应直接在本地运行。
