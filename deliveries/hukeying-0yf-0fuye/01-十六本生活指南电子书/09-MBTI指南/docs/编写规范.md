# 编写规范

[← 回总目录](../README.md)

## 一、条目字段

每条固定 10 个字段，顺序不变，缺一个 `build.py --check` 就会报错。

| 字段 | 写什么 | 长度 |
| --- | --- | --- |
| 情况 | 一个具体处境，带场景细节 | 15 到 40 字 |
| 判断 | 这件事的性质与处理原则 | 30 到 80 字 |
| 原话 | 一句能直接说出口的话，用「」包住 | 20 到 60 字 |
| 回应 | 对方最常见的两种反应，缩进两格 | 每行 20 到 50 字 |
| 接着做 | 一到三个可执行动作 | 20 到 60 字 |
| 做对了 | 可观察的过关标准 | 15 到 40 字 |
| 红线 | 一个具体不能做的动作 | 15 到 40 字 |
| 依据 | A/B/C/D 加一句理由 | 15 到 60 字 |
| 来源 | S01 这类编号，对应 SOURCES.md | 1 到 3 个 |
| 相关 | 两到三个条号 | 2 到 3 个 |

## 二、证据分级

| 等级 | 含义 | 写法 |
| --- | --- | --- |
| A | 法律与规章原文可查 | 写明法律名称与条款；不确定就不给 A |
| B | 有可检验的研究支撑 | 写概念名与研究者，不写编造的比例数字 |
| C | 实务与经验归纳 | 必须带「因人而异」的前提 |
| D | 本书编写情境与话术 | 只能用于「原话」与具体场景 |

**禁止**：把 D 级话术写成 A 级结论；用「研究表明」却不给研究；把流行说法写成科学共识；编造统计数字。

## 三、红线怎么写

红线必须是**动作**，不是态度。本书的四条总红线：

- 不把 MBTI 用于录用、晋升、考核。
- 不用类型定义人或评价能力。
- 不把类型写进简历、绩效材料与档案。
- 不替代心理评估、职业咨询与临床诊断。

每条红线都要能回答：如果做了，后果是什么。

## 四、话术怎么写

1. 短。一句能说完，不超过两口气。
2. 有场合。标明当面、微信还是电话。
3. 不阴阳。不用反问、不用嘲讽。
4. 给出替代。拒绝和设界时尤其要给一个能做的事。
5. 不承诺做不到的事。

## 五、案例纪律

- 所有对话为编写情境，不挂真人姓名、单位名。
- 不把网络流传的「真实案例」当一手材料，最多按 C 级引用。
- 不写具体研究数字与百分比。

## 六、每章写完的自查

- [ ] 没有把标签当成事实、诊断或能力判断
- [ ] 没有把流行说法写成科学共识
- [ ] 涉及法律与安全的条目写了依据与渠道
- [ ] 危机类内容给出了 110 / 120 / 12356 等渠道
