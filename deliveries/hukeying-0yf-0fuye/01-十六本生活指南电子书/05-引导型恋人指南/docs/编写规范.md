# 编写规范

[← 回总目录](../README.md)

给以后改这本书的人。`book/` 是正文源，其他阅读页都是生成的。

## 文件结构

- `book/NN-章节名.md`：一章一个文件，文件名带两位章号。
- `data/selfcheck.json`：32 题自查，改了题要重新构建。
- `SOURCES.md`：来源表，`SXX` 编号只能加，不能重用。
- `PATTERNS.md`：22 个对话模式，编号 `P01` 到 `P22`，改数量要同时改 `tools/build.py` 的校验。
- `GUIDE.md`、`index.html`、`selfcheck.html`、`downloads/`：生成物，不手改。

## 一条长什么样

````markdown
### 5.2 不追着把话说清楚
<!-- 标签: 成本=0 时间=少 难度=高 收益=大 场景=冲突 依据=A -->
- 情况：对方说“现在不想谈”，你更想立刻谈完。
- 判断：追着要答案，会把对方推到只能逃的位置。
- 第一句：“你现在不想谈，我不追。我们定一个最晚时间：明天晚上九点。”
- 回应：
  - 「明天再说」→ “好，明晚九点。我不在这之前发消息。”
  - 「你别走」→ “我不走，但我不在门口站着。九点我回来。”
- 接着做：物理上退开；这期间做自己的事；到点只问一次。
- 做对了：你没有用追击换到一句敷衍的“好好好”。
- 红线：不堵门、不抢手机、不跟着进洗手间；不用自伤威胁。
- 依据：A。要求、退缩循环的研究一致显示，追压会强化退缩。
- 来源：S05、S06、S21
- 相关：2.4、5.3、3.5
````

字段一个都不能少，`回应`必须两条。`相关`必须指向存在的条号。

## 八条硬规矩

1. **一条只解决一个处境。** 标题里出现“和”“以及”时，想想是不是该拆。
2. **第一句必须能直接说出口。** 不超过三行，用引号，允许对方拒绝。
3. **红线必须写。** 没有红线的条目，等于在鼓励照搬。
4. **不贴诊断。** 可以写“他在被要求立刻表态时会退”，不能写“他是回避型”。
5. **不承诺结果。** 不写“这样 TA 就会回心转意”“成功率 80%”。
6. **不写操控。** 查手机、装定位、冷暴力、吃醋测试、PUA，一律进红线，不进方法。
7. **不替代专业帮助。** 暴力、成瘾、自伤、精神疾病，转介，不自己治。
8. **示例标清楚。** 所有对话是编写情境，不是真人记录；引用公开材料要标来源与偏差。

## 证据怎么写

- 先定等级，再写理由，再给来源。
- 一条主张只挂真正支持它的来源，不拿一篇论文撑五条不相干的结论。
- 来源表要写“核对状态”：全文、摘要、二手概述、检索摘要、未核对。
- 二手概述不能写成“研究证明”。
- 数字只在核到原始出处时保留，并写清它不能说明什么。
- 流行说法（爱的五种语言、5:1 魔法比例、连接邀请 86%）要么降级，要么删除，要么标明“科普著作，未核到原始统计”。

## 风格

- 简体中文，短句，口语化，不用感叹号。
- 不写“姐妹们”“兄弟们”这类假定读者的称呼。
- 不爹味，不说教，不替读者做道德判决。
- 不用中文长破折号，需要停顿时用逗号、冒号、括号或句号。
- 专业词第一次出现时用日常话解释一句。
- 不写“显然”“众所周知”。

## 改完怎么验

```bash
python3 tools/build.py --check
python3 tools/build.py
```

第一条必须输出：

```
OK 96 entries, 12 chapters, 31 sources, 22 patterns
```

改了条数、章数、来源数或模式数，要同步改 `tools/build.py` 里的期望值，以及 `docs/验收报告.md` 的数字。

改了 `partner-guide-audit` 的规则，再跑：

```bash
cd skills/partner-guide-audit
python3 scripts/audit.py --bench
```

必须 12/12。不要为了让新案例通过而放宽红线；先改规则，再改期望。

## 来源怎么加

1. 在 `SOURCES.md` 表尾加一行 `SXX`，写清作者、年份、标题、期刊/机构、链接。
2. 标类型、等级、核对状态。
3. 写“用来支持什么”，一句，具体。
4. 条目里的 `来源` 只写 ID，不写长引用。
5. 找不到原文就写“未核对”，不要编 DOI 或页码。

## 撤回与纠错

发现某条不成立：

1. 先改条目，必要时降级或删除。
2. 在 `SOURCES.md` 的“核实记录：哪些话被删掉了”里加一行，写清原说法、处理、原因。
3. 如果是安全问题，优先修，不等下一版。
4. 改了行为或条号，检查 `相关`、自查题、模式库、验收报告里的引用。
