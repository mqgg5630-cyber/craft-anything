# 7. 深挖回合：接住连环追问

[← 回总目录](../README.md)

初面看匹配，复面看深度。深挖回合的特点是：你说什么，对方就往里问一层，直到你答不出或者露出底牌。它不是在找完美答案，是在找你的能力边界。

这一章讲六种常见形态：连环追问、现场编码、方案设计、案例估算、作品讲解、群面。每一种都有固定的应对骨架，练三次就能稳定。


### 7.1 连环追问的五步

- 情况：一个问题被追了五层，从「你做了什么」追到「你凭什么这么判断」，你开始重复自己。
- 判断：每一层追问都在缩小范围。稳住的方法是：先复述问题边界，再给结论，再给依据，最后标出不确定的地方。
- 原话：「您问的是〔复述〕对吗？我的结论是〔一句〕，依据是〔数据或经验〕，其中我不确定的是〔部分〕，那部分我当时是按〔假设〕做的。」
- 回应：
  - 「假设错了怎么办」→ 「那结论会反过来，具体会变成〔另一种判断〕。」
  - 「你怎么验证的」→ 「用〔指标〕看了〔时长〕，样本是〔范围〕，所以只对这类情况成立。」
- 接着做：给每段核心经历准备「五层问答树」，第五层必须能落到一个具体的数字或文件。
- 做对了：你能明确说出「这里我不确定」，而不是把所有话都说成确定。
- 红线：不要被追问就改结论，也不要硬撑到自己都不信。
- 依据：C。追问链用于探测能力边界与诚实度。
- 来源：S16、S12
- 相关：3.3、4.5

### 7.2 现场编码与作业

- 情况：面试官丢来一道题，说「你先讲思路，再写」。
- 判断：现场题的评分点不只是写对，还包括沟通、边界处理、测试意识。先复述题意、给例子、说复杂度，再动手。
- 原话：「我确认一下：输入是〔范围〕，空值和重复怎么处理？我打算用〔思路〕，复杂度是〔时间和空间〕，先写主流程再补边界。」
- 回应：
  - 「你的代码有问题」→ 「是这一类输入吗？我加一个判断，顺便补两个测试用例。」
  - 「有没有更快的做法」→ 「有，用〔方法〕能把复杂度降到〔阶〕，代价是〔可读性或内存〕。」
- 接着做：每天手写一道中等难度题，写完自己口述思路两分钟，练到能边说边写。
- 做对了：你在写之前说清了假设，写完之后主动给了测试用例。
- 红线：不要背答案装作临场想出来，不要在被指出问题时争辩。
- 依据：C。现场编码评估同时覆盖正确性、沟通与测试习惯。
- 来源：S12、S16
- 相关：5.1、7.3

### 7.3 方案设计与系统设计

- 情况：被要求设计一个系统或一套方案，你直接开始讲技术选型。
- 判断：设计题考的是从需求到取舍的过程。固定五步：问清规模与约束、给出高层结构、算容量、谈瓶颈、说扩展。
- 原话：「先确认三件事：用户量级、读写比例、能不能接受最终一致。我按〔量级〕设计：入口是〔组件〕，存储是〔选择〕，因为〔原因〕。瓶颈会出现在〔环节〕，扩展方式是〔做法〕。」
- 回应：
  - 「数据量再涨十倍」→ 「先分片，再考虑缓存，具体会先在〔环节〕加一层。」
  - 「为什么不用现成的服务」→ 「可以用，如果〔条件〕成立；现在的问题是需要定制〔部分〕。」
- 接着做：准备三个能画出来的方案（高读、高写、强一致），练到白板上十分钟能讲完一个。
- 做对了：你先问约束再画图，并且主动指出了瓶颈。
- 红线：不要背通用架构图，不要在不了解的场景硬套微服务。
- 依据：C。系统设计面试的标准评估维度是需求澄清、容量估算、权衡与扩展性。
- 来源：S12、S16
- 相关：5.1、7.4

### 7.4 案例与估算题

- 情况：被问「估算这个城市一年卖出多少杯咖啡」，你愣住。
- 判断：估算题不考答案，考拆解。把它拆成「人口、渗透率、频次、单价」四层，每一层给一个可解释的假设。
- 原话：「我按四层拆：这个城市常住人口〔数〕，喝咖啡的比例〔假设和理由〕，人均每周〔杯数〕，一年〔周数〕。乘起来是〔结果〕，我认为误差主要来自第二层。」
- 回应：
  - 「你凭什么这么假设」→ 「参考的是〔公开数据或常识〕，如果实际是〔另一值〕，结论会变成〔区间〕。」
  - 「真实数字差很多」→ 「差在哪个假设？如果是〔层〕，说明我对这类人群的判断偏乐观。」
- 接着做：练五个常见估算（市场容量、订单量、成本结构），每个都用四层拆解，写清假设来源。
- 做对了：你给出了区间而不是一个精确到个位的数字，并指出最脆弱的一层。
- 红线：不要编造「据研究显示」的假数据，卡住时可以说「这里我需要一个假设」。
- 依据：C。案例面试评估结构化拆解与假设管理。
- 来源：S16、S17
- 相关：5.2、5.3

### 7.5 作品讲解与白板

- 情况：让你讲作品，你从第一页翻到最后一页。
- 判断：作品讲解是引导式陈述，不是展示。先给结论，再给关键决策，最后给数据。每页只讲一句，留时间给对方提问。
- 原话：「这个作品解决的是〔问题〕。我从三页讲完：第一页是问题，第二页是我的方案和放弃的方案，第三页是结果。您想先看哪一页？」
- 回应：
  - 「这里为什么不这样设计」→ 「试过，问题在〔具体代价〕，所以我换成了现在这版。」
  - 「这是你一个人做的吗」→ 「视觉是我，交互是〔角色〕，我负责的是〔边界〕。」
- 接着做：把作品集压到六页，每页写一句「这一页想让人记住什么」，讲的时候先说这句。
- 做对了：对方在第三分钟就开始问具体问题，而不是让你继续翻。
- 红线：不要放非自己主创的内容，不要在被质疑时改口说「这是团队做的」。
- 依据：C。作品陈述的评估重点是决策透明度。
- 来源：S16、S17
- 相关：5.5、2.2

### 7.6 群面与无领导讨论

- 情况：六个人一组讨论一个案例，有人抢话，你插不进去。
- 判断：群面看的是你在团队里的功能位，不是谁说得最多。有效的角色有三种：定框架、做计时与收束、做记录与总结。抢话是最容易被扣分的。
- 原话：「我先用一分钟把问题拆成三块：〔A、B、C〕，我们按这个顺序讨论，二十分钟里每块六分钟，最后留两分钟总结，可以吗？」
- 回应：
  - 「我先说我的观点」→ 「好，您先说，我记一下，等下一起对齐。」
  - 「时间不够了」→ 「那我们把 C 留作建议，先定 A 和 B 的结论。」
- 接着做：赛前准备三个开场句式（定框架、拉回时间、总结），全场只用这三个，不多说。
- 做对了：讨论结束时，总结用的是你搭的框架，或者你被推举做总结。
- 红线：不要打断别人，不要为了表现否定所有人的观点，不要抢着做唯一发言者。
- 依据：C。无领导小组评估维度包括组织、协作与影响力。
- 来源：S16
- 相关：4.4、3.6
