# 5. 按岗位问：八类岗位各考什么

[← 回总目录](../README.md)

同一句「你最大的成就」，技术岗想听你把一个系统做稳，销售岗想听你把一个单子签下，职能岗想听你把一个风险堵住。岗位不同，证据的形态就不同。

本章按八类岗位各给一条：考察重点、必问的三道题、一段可直接改的原话、以及两种追问的接法。没在列表里的岗位，按最接近的那一类套。


### 5.1 技术研发岗

- 情况：面试技术岗，被问「讲讲你最近做的项目」，你从需求背景讲到上线，讲了八分钟。
- 判断：技术面看三样：代码与系统的基本功、你负责的边界、出问题时的定位能力。讲项目要主动给出「难点、方案取舍、你写的部分、怎么验证」。
- 原话：「这个系统的难点在〔并发或数据一致性或性能〕。我负责〔模块〕，方案的取舍是〔A 与 B〕，最后选 B 是因为〔约束〕。上线后我们盯了三个指标：〔延迟、错误率、资源占用〕，稳定在〔数值〕。」
- 回应：
  - 「为什么不用某某框架」→ 「评估过，它在〔场景〕下更合适，但我们的〔约束〕不允许，代价是要自己维护〔部分〕。」
  - 「如果流量涨十倍呢」→ 「第一个瓶颈会出现在〔环节〕，我会先做〔具体动作〕，而不是直接加机器。」
- 接着做：给每个项目写一页「架构、取舍、故障、指标」，另备两段能手写的最小实现。
- 做对了：你能在白板上画出数据流，并指出哪一段最容易出错。
- 红线：不要把团队架构说成自己设计的，不要在不会的技术上硬答。
- 依据：C。技术面通用结构为项目、基础、设计、编码四段。
- 来源：S12、S16
- 相关：7.2、7.3、3.3

### 5.2 产品经理岗

- 情况：被问「你怎么决定做这个功能」，你答「根据用户反馈和老板要求」。
- 判断：产品岗看四样：需求来源是否可验证、判断依据、跨团队推进、上线后的数据结论。忌只讲流程，不讲取舍。
- 原话：「这个需求来自〔数据或访谈〕，我们判断值得做，是因为〔影响面〕和〔成本〕。我先做了〔最小验证〕，结论是〔数据〕，于是排进〔优先级〕。上线后〔指标〕从〔A〕到〔B〕，没达到预期的是〔部分〕，原因是〔判断〕。」
- 回应：
  - 「如果开发说做不了」→ 「我会先拆到能做的范围，再和〔角色〕约一个复盘点，不硬压排期。」
  - 「这个功能没成功吧」→ 「没达到目标，我复盘出的问题是〔具体〕，下一版改了〔做法〕。」
- 接着做：准备两个案例，一个成、一个败，都要带上线后的真实数字与你的判断失误。
- 做对了：你的答案里有取舍，也有一个失败的功能。
- 红线：不要把老板的需求包装成你的洞察，不要虚构数据看板。
- 依据：C。产品岗评估以决策质量与结果归因为主。
- 来源：S16、S17
- 相关：7.4、4.3

### 5.3 运营岗

- 情况：被问「你怎么做增长」，你列了一堆活动形式。
- 判断：运营岗看三样：你的动作是否可复用、指标拆得够不够细、投放与活动的成本意识。活动形式谁都会说，差别在「算过账」。
- 原话：「我负责的那条线是〔渠道或内容或社群〕，月预算〔金额〕，我做的三件事是〔动作〕。核心指标是〔ARPU 或留存或转化率〕，从〔A〕到〔B〕，单位获客成本从〔C〕降到〔D〕。」
- 回应：
  - 「这个增长是买来的吧」→ 「有一部分是，我把付费和自然量分开算了，自然量部分靠的是〔机制〕。」
  - 「换个行业你能做吗」→ 「能迁移的是拆指标和算账的方法，不能直接搬的是渠道红利。」
- 接着做：给每个项目补一张小表：投入、产出、单位成本、可复用机制。面试时只报这张表。
- 做对了：你能立刻说出一个做过但没效果的活动，以及为什么没效果。
- 红线：不要把平台补贴带来的增长说成运营能力，不要用虚荣指标（曝光、粉丝数）当结论。
- 依据：C。运营岗评估以指标拆解与单位经济模型为核心。
- 来源：S09、S16
- 相关：5.4、7.4

### 5.4 市场与品牌岗

- 情况：被问「你做过什么campaign」，你讲了创意的灵感来源。
- 判断：市场岗看两样：创意背后的判断依据，以及花钱的效率。品牌岗还会看你能否说清「这个内容为谁解决什么问题」。
- 原话：「这一轮传播的目标是〔认知或转化〕，人群是〔画像〕，我们选〔渠道组合〕是因为〔依据〕。预算〔金额〕，最终〔曝光或转化〕是〔数字〕，单次转化成本〔数字〕，我认为有效的是〔部分〕，无效的是〔部分〕。」
- 回应：
  - 「这个爆款是运气吧」→ 「有运气，但我们复用过两次同一套结构，成功率大概〔比例〕。」
  - 「不看数据你怎么判断创意好坏」→ 「先看它有没有说清一个具体利益点，再看它能不能被一句话复述。」
- 接着做：整理三个案例，每个都写出「目标、人群、渠道、预算、结果、复盘」，附一张截图。
- 做对了：你能说清一次失败的投放，亏在哪一步。
- 红线：不要把公司投放预算说成自己的创意功劳，不要虚报传播数据。
- 依据：C。市场岗评估聚焦目标、资源与结果的匹配。
- 来源：S16、S09
- 相关：5.3、4.4

### 5.5 设计岗

- 情况：面试让你讲作品集，你从头讲风格和配色。
- 判断：设计岗看三样：问题定义、方案取舍、落地成本。作品讲得好不好，取决于你能不能说出「为什么不是另一个方案」。
- 原话：「这个项目的问题是〔用户在哪一步卡住〕，我给的方案是〔改动〕，取舍是〔体验与开发成本〕。上线后〔指标〕变化是〔数字〕，我放弃的方案是〔方案〕，因为它会让〔代价〕。」
- 回应：
  - 「这个改动太小了吧」→ 「小，但它影响的这一步占流程的〔比例〕，改动成本只有〔工时〕。」
  - 「你偏视觉还是偏交互」→ 「我偏解决问题，视觉是我的工具，判断标准是能不能降低理解成本。」
- 接着做：作品集只放六个项目，每个配一页「问题、方案、取舍、结果」，删掉纯视觉摆拍。
- 做对了：你能说出一个被否掉的方案，以及否掉它的理由。
- 红线：不要放非自己主创的作品，不要把临摹稿当项目。
- 依据：C。设计岗评估以问题定义与落地权衡为主。
- 来源：S16、S17
- 相关：7.5、3.3

### 5.6 销售岗

- 情况：被问「你业绩怎么样」，你说「我一直是团队前几名」。
- 判断：销售岗只看三样：你卖的是什么、周期多长、你自己签的还是跟单。数字要给全：客单价、成单周期、回款、续约。
- 原话：「我卖的是〔产品〕，客单价〔金额〕，平均成单周期〔天〕，去年完成〔金额或达成率〕。我的打法是〔具体方法〕，最难的一单是〔例子〕，卡在〔环节〕，我用〔动作〕推进的。」
- 回应：
  - 「这些客户是公司给的吗」→ 「七成是分配的线索，三成是我自己开发的，开发方式是这个。」
  - 「换个行业你还行吗」→ 「可迁移的是识别需求和推进节奏，需要补的是产品知识和决策链。」
- 接着做：准备三个数字：达成率、客单价、回款周期，再加一个「最难的单子」完整复盘。
- 做对了：你能说出一次丢单的原因，且不怪客户。
- 红线：不要把团队业绩算成个人，不要承诺做不到的条款换单子。
- 依据：C。销售岗评估以可核验的业绩结构与过程能力为主。
- 来源：S16、S09
- 相关：2.2、4.4

### 5.7 职能岗（财务、HR、法务、行政）

- 情况：面试职能岗，被问「你的价值在哪」，你答「支持业务」。
- 判断：职能岗看两样：专业判断的准确度，以及你在「挡住风险」和「不添麻烦」之间的平衡。只讲服务会被认为没原则，只讲合规会被认为难合作。
- 原话：「我负责〔模块〕，去年处理〔数量〕笔，发现并拦下〔事例〕。我的原则是先把风险说清，再给两个可执行的方案让业务选，不直接说不。」
- 回应：
  - 「业务坚持要违规操作呢」→ 「我会书面留痕并上报，同时给他一个合规的替代路径。」
  - 「你怎么证明价值」→ 「用三个数：差错率、处理时效、被采纳的改进建议数。」
- 接着做：准备两个「我拦下了什么」和两个「我改进了什么」，都要有具体金额或时长。
- 做对了：你能说清一次坚持原则的代价，以及你怎么把关系维持住。
- 红线：不要泄露前公司薪酬数据、员工信息、案件细节。
- 依据：C。职能岗评估以专业准确性与协作平衡为主；A。个人信息与商业秘密的保密义务有法律基础。
- 来源：S16、S01
- 相关：9.5、11.2

### 5.8 应届生与转行

- 情况：应届或转行，没有对口经验，面试官说「你没有相关经历」。
- 判断：没有经历时，用三样东西替代：可验证的作品、可迁移的能力、明确的补课计划。作品比自述有用十倍。
- 原话：「我确实没有正式的项目经历，但我做了三件事证明我能做：一是〔作品或复现项目，给链接〕，二是〔可迁移能力，举一个具体场景〕，三是这三个月我在补〔技能〕，进度是〔具体〕。」
- 回应：
  - 「这些是练手，不算经验」→ 「对，所以我按你们真实的业务做了一遍，这是结果和我踩的坑。」
  - 「你为什么转行」→ 「我原来做的〔A〕和这个岗位共用的能力是〔B〕，我缺的是〔C〕，已经补到〔程度〕。」
- 接着做：做一个「能看的东西」：把一个公开需求从零做到可演示，附上过程文档和复盘。
- 做对了：面试官主动问你要了作品的链接或演示。
- 红线：不要把课程作业说成商业项目，不要买「项目经历包装」服务。
- 依据：C。能力信号的可验证性高于经历标签；D。写作组案例。
- 来源：S23、S17
- 相关：4.6、2.4
