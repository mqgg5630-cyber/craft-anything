# 编写规范

这本书的每一条都按同一套字段写。规范的目的不是统一文风，是让每条都能被检索、被引用、被核对。

## 条目结构

```
### 9.2 试用期的三个数字
- 情况：读者遇到的具体场景，一句话，写清对方说了什么。
- 判断：这一条在讲什么规则，两到三句，先给结论。
- 原话：能直接说出口的一句话，带场合（面试现场 / 邮件 / 电话）。
- 回应：
  - 「对方可能这样说」→ 「你这样接」
  - 「对方也可能这样说」→ 「你这样接」
- 接着做：一到三个动作，按先后顺序。
- 做对了：这一步过关的判据，可观察。
- 红线：一个具体不能做的动作。
- 依据：A/B/C/D 加一句理由，涉及法条写明条款。
- 来源：S01、S02
- 相关：11.2、11.3
```

## 字段规则

| 字段 | 长度 | 必须回答的问题 |
| --- | --- | --- |
| 情况 | 20 到 60 字 | 读者在什么场景下会用到这一条 |
| 判断 | 30 到 80 字 | 这件事的本质是什么，为什么会这样 |
| 原话 | 20 到 60 字 | 读者张嘴第一句说什么 |
| 回应 | 必须两条 | 对方最常见的两种反应，以及接法 |
| 接着做 | 20 到 50 字 | 说完之后下一步做什么 |
| 做对了 | 15 到 40 字 | 怎么判断这一步做对了 |
| 红线 | 15 到 40 字 | 什么动作绝对不能做 |
| 依据 | 一句 | 这条说法的强度 |
| 来源 | 至少一条 | 能查到出处 |
| 相关 | 一到三条 | 相邻处境 |

## 写作纪律

1. **一条一个处境。** 一条里塞两个问题，读者会不知道该做哪个。
2. **原话必须能直接说。** 出现「适当沟通」「注意分寸」这类词就重写。
3. **不用破折号。** 用逗号或冒号。`build.py --check` 会拦。
4. **不写没有出处的数字。** 薪资、比例、期限，要么标 A 法条，要么标 B 数据并写清样本，要么不写。
5. **不写「一定能」「保证」。** 招聘是概率，合同是个案。
6. **案例是编写情境。** 不搬运真人聊天记录、不点名公司、不写可识别的个人信息。
7. **不贬低任何一方。** 面试官不是敌人，公司不是骗子，除非有具体证据。

## 证据分级

| 等级 | 判据 | 例子 |
| --- | --- | --- |
| A | 法条、司法解释、官方文件原文可查 | 试用期上限、二倍工资、竞业补偿 |
| B | 有公开数据、报告或同行评审研究 | 招聘漏斗、结构化面试效度 |
| C | 行业共识、权威方法论著作 | STAR、四格决策表、锚定效应 |
| D | 本书原创话术与情境 | 所有「原话」、具体接法 |

## 章节规则

- 每章 6 条，岗位章与合同章 8 条。
- 章首必须有一段导语，说清这一章解决什么、按什么顺序读。
- 章内条目按读者遇到问题的先后排，不按重要性排。
