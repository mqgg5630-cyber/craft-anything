# 小红书链接 → 先下载原片 → 10张复刻

## 严格区分另一份 Skill
- 本 Skill：链接输入，笔记原片先下载，输出10张同系列独立壁纸。
- `../one-reference-suite/SKILL.md`：单图输入，手机/电脑/iPad/手表/情头/朋友圈/QQ/聊天等用途适配全套。
- 两者不能因为都使用10次生图就混为一谈。本流程不自动生成UI、情头、多设备尺寸、动态或33素材清单。
- 用户选择的09「可可晚安灯串」属于全套 Skill 的聊天默认，不覆盖本流程参考笔记的画风、配色和构图。

## 1. 解析笔记
1. 读取短链跳转，记录原链接、最终链接、笔记ID、作者、标题、文案及有序图片URL。
2. 对轮播重复URL去重，排除头像、二维码、评论表情。实际3张就是3张参考，不得说下载了10张原片。
3. 区分原帖图片与作者提供的无水印/高分辨率原文件。网页CDN展示图可能压缩、带水印，不得未经确认称为作者无损原图。

## 2. 原片下载硬门槛（生成前必须通过）
- 下载全部可取得的笔记图片至新目录 `source/`，保留原始字节；禁止覆盖既有交付。
- 清单逐张记录：序号、源URL、路径、字节数、格式、宽高、MD5、来源质量（网页展示图或已确认原文件）。
- 实际解码并人工看图；不能只凭文案、封面链接或搜索缩略图生成。
- 当前环境直连失败时，先查仓库已有成功下载路径，不应立即把下载工作交回用户。本仓库已有 GitHub Actions 公共原片下载流程（`.github/workflows/wallpaper-download.yml`，共用 `tools/wallpaper-job/download.py` 的大小/解码/尺寸校验）。使用已授权 GitHub 工作流仅下载公开笔记图片，刷新页面CDN地址，在当前工作分支写回校验后的参考文件；不切换或推送其他分支，不更改网络策略或绕过访问权限。小王子示例见 `download_little_prince.py` 与独立工作流。
- 分享页进入 `/login` 不等于历史已记录的公开图片 URL 也不可用。先用 GitHub branches/tree 和 Actions runs/jobs 检查其他分支，按同一分享链接／笔记 ID 定位已成功的 `source-manifest.json`，保留来源提交与运行证据；只读取其他分支，在当前分支建立 `source-seed.json`，由 Actions 重新下载那些精确的公开地址并完整解码、比对历史 MD5/SHA-256。不要猜资源标识或伪造签名，也不重试突破登录页。奔夕阳完整成功案例见 `deliveries/lululu-sunset-b7/历史成功流程复盘.md`、`download_sunset_b7.py` 与运行 `45017752842`（5张PNG）；之前只查当前分支并在登录跳转后停止会漏掉该回退路径。
- 成功路径仍失败时才记录 `blocked_source_download`，明确告诉用户实际卡点及尝试结果；最后才请求用户上传原片或提供已授权云盘位置。不得用想象图冒充下载结果，也不先生成后补参考。
- 不尝试绕过登录、权限和网络限制，不收集账号密码、Cookie或令牌。

## 3. 参考分析与10张方案
- 从下载的原片识别角色、服饰、比例、场景、画风、色盘、光影、颗粒与留白。
- 默认保留整个笔记系列的风格分组；用户明确限定某一款时才全部按该款。保留所有原片用于审计，不把文案出现的第一款自动当成唯一指定款。
- 参考数量不限制输出数量：1张参考即可开始复刻10张，3张参考也输出10张，不要求凑齐10张原片，不为数量问题再次征求确认。前提是参考文件已实际取得且看过。
- 若原帖仅3张，10张是以3张为参考的复刻/轻微变体，不是10张逐一对应原帖；记录每张输出对应参考及允许变化。
- 每次生成1张独立壁纸，附对应原始下载图；不得递归用前一张生成图替代原参考，不生成拼版后裁成10张。
- 尽量贴近原图，除非用户要求，不擅自换梦幻水彩等风格；不得把复刻结果标为作者原片。
- 用户反馈“风格太一致，换10张”不能直接理解为授权换绘画媒介。经本次纠正，优先保留原片笔触、材质、角色比例和整体质感，通过姿态、镜头、互动、场景构图与云层星河等内容变化增加差异；避免只挪星星，也避免极端改成纸雕、黏土、矢量等无关风格。仅用户明确指定新媒介时才切换。可复用已下载核验的参考，不要求重新传图。新目录保留旧版。
- 工具选项遵循宿主规则；10张不同交付属于大批量任务，不额外生成多组风格候选。

## 4. 交付与验收
新目录结构：
- `source/`：实际下载的笔记参考原片，保持原始字节。
- `images/`：10张独立复刻PNG，连续编号01至10。
- `source-manifest.json`：下载来源、格式、尺寸和哈希。
- `output-manifest.json`：输出→参考映射、尺寸、字节、MD5及变更说明。
- `README.md`：来源、实际下载数量、原片质量限制、复刻数量、交付与验收状态。
可另附总览，但不能替代10张独立图。无HTML/空文件夹/仅ZIP交付。

验收：下载文件可解码且已看过；输出恰好10张、逐张解码/尺寸/非空/哈希；人工核对角色与风格；不将插值称作原生新增细节。若用户要求云盘交付，先上传全部独立文件，再重新列目录核对数量与MD5；未验证不得声称全部云端完成。

## 任务停止条件
原片未下载或尚未看过 → 不生成。输出不足10张 → 不声称完成。云端未验收 → 只报告已完成部分与实际卡点。
